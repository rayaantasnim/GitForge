Ecosystem 01 · Extension Runtime

Zero-Privilege WebAssembly Extension Runtime

Traditional IDE extensions run with full operating system privileges, exposing developers to credential theft and malicious file exfiltration. GitForge sandboxes all extensions inside isolated WebAssembly modules with capability-based security.

Plugins must explicitly declare requested capabilities (e.g. read current AST node, register gutter icon, emit linter diagnostics). Host function calls are intercepted and permission-checked in constant time.

Ecosystem 02 · Registry Layer

Decentralized Marketplace & Cryptographic Attestation

Extensions in the GitForge Marketplace are signed via Sigstore and Rekor transparency logs. Before any plugin binary is downloaded to a developer's machine, its Merkle root signature and author identity certificate are checked against the ledger.

Enterprises can mirror the registry internally, enforcing bespoke compliance policies, automated static vulnerability scanning, and license whitelisting on all third-party additions.

Sigstore Transparency · Automated CVE Scans · Private Air-Gapped Mirrors
Ecosystem 03 · Tooling Standard

Bidirectional Language Tooling & Debug Adapter Protocol

Debugging complex multi-service architectures requires synchronized breakpoints across distributed runtimes. GitForge implements the full Debug Adapter Protocol (DAP) extended with reverse-stepping and memory inspection capabilities.

Step from a TypeScript frontend handler directly into a Rust microservice backend breakpoint across an active WebSocket RPC session without losing stack traces or local variable bindings.

Debugger Protocol: Extended DAP 2.2 / LLDB Bridge
