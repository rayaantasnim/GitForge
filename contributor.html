Guideline 01 · RFC Consensus Protocol

Architectural Governance & RFC Consensus Lifecycle

Every substantive change to internal C++23 kernel headers, WebAssembly interfaces, or AST serialization requires a formal Request for Comments (RFC). RFCs undergo a minimum 14-day technical review window by the Core Architecture Council.

Proposals must outline concrete microbenchmark criteria, cache miss profiles, and fallback mitigations before receiving unanimous consensus approval.

Guideline 02 · Version Control Standards

Strict Semantic Branching & Hermetic PR Protocol

We enforce a linear git history without merge bubbles. Branch names must follow the semantic taxonomy: feat/core/<topic>, fix/wasm/<topic>, or perf/simd/<topic>.

Every commit message must satisfy the Conventional Commits specification, referencing tracked GitHub issue IDs and including signed cryptographic DCO (Developer Certificate of Origin) tags.

Strict Linear Rebase · Semantic Conventional Commits · DCO Sign-off Required
Guideline 03 · Quality Verification

Deterministic Test Matrices & Hermetic Re-Entrancy

Test execution must be 100% deterministic with zero flaky passes. Every test suite runs inside isolated network-isolated cgroups where system clocks and random seeds are frozen to predictable vectors.

Pull requests that decrease line or branch coverage by even 0.01% are blocked automatically by our CI bot, preserving the absolute reliability of the GitForge core engine.

Coverage Gate: 95.00% Strict Monotonic Invariant
Property-based testing via QuickCheck/Hypothesis runs on all state mutations to uncover edge-case regressions.

Guideline 04 · Review Efficiency

High-Performance Contribution Pipeline & 24h SLA

We respect community contributors' time. Maintainers guarantee an initial thorough code review within 24 hours of submission. Automated CI bots post comprehensive performance diffs comparing memory consumption and instruction counts.

If an author's PR meets all safety checks and passes benchmarking matrices, it is fast-tracked into the nightly integration branch without administrative delay.

Review SLA: < 24 Hours
Automated Perf Bot: Instruction-Level Diffs
Merge Criteria: 2 Senior Approvals
Guideline 05 · Cryptographic Trust

Security Disclosure & Cryptographic Commit Signing

All code submissions must be cryptographically signed using GPG or SSH keys verified against GitHub identity profiles. Unsigned commits are immediately rejected by branch protection rules.

Security researchers discovering vulnerabilities are invited to submit through our encrypted PGP security portal, with bug bounties awarded in accordance with CVSS v3.1 severity scores.

Signature Requirement: Ed25519 or RSA-4096 GPG
Vulnerability SLA: 4-Hour Acknowledgement
